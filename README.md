# CS 210: Temperature Conversion Program

## Project Overview

This C++ program reads a list of cities and their average yearly temperatures in Fahrenheit from a text file, converts those values to Celsius, and writes the results to a new text file. The output includes a section with temperatures displayed to two decimal places and a separate section with temperatures rounded to whole numbers. The goal was to practice file input/output while creating a program that can take existing information, process it, and organize the results in a useful format.

## Project Files

- `TemperatureConverter.cpp` — C++ source code for reading, converting, and writing temperatures.
- `FahrenheitTemperature.txt` — sample input with six cities and Fahrenheit temperatures.
- `CelsiusTemperature.txt` — sample output generated by the program.

## How to Run

Compile the source file with a C++11-compatible compiler:

```bash
g++ -std=c++11 TemperatureConverter.cpp -o temperature_converter
```

Run it from the project directory so the program can locate the input file:

```bash
./temperature_converter
```

On Windows, run `temperature_converter.exe` instead. The program creates or overwrites `CelsiusTemperature.txt` in the current working directory.

**Input format:** Each line should contain a single-word city name and a numeric Fahrenheit temperature, separated by a space. This project includes six sample entries.

## CS 210 Portfolio Reflection

### Summarize the project and what problem it was solving.

For this project, I developed a C++ program that reads temperature data from an existing text file, converts Fahrenheit values into Celsius, and writes the results to another file. I also included a separate section with rounded Celsius values so the output is easier to reference when precise decimal values are not necessary. The project demonstrates how a program can work with information stored outside of the application instead of depending entirely on user input through the console.

### What did you do particularly well?

I think one of the stronger parts of this project is how the output is organized. Rather than only displaying the converted values, I kept the more precise temperatures and the rounded values in separate sections. This makes the information easier to read without losing the original calculation results. I also focused on keeping the conversion formula straightforward and documenting what each part of the program is responsible for.

### Where could you enhance your code? How would these improvements make your code more efficient, secure, and so on?

One improvement would be to support city names containing spaces, since the current input format expects each city name to be a single word. I could also expand the input validation to give more specific feedback when a record is incomplete or a temperature is not numeric. Another improvement would be to allow the user to choose the input and output filenames instead of keeping them fixed. These changes would make the program more flexible and reduce the chance of unexpected behavior when working with different files.

### Which pieces of the code did you find most challenging to write, and how did you overcome this? What tools or resources are you adding to your support network?

The part that required the most attention was managing the file input and output correctly. It is important to understand not only how to perform the temperature conversion but also how the program reads each record and writes the results in the intended format. I approached this by breaking the process into smaller steps and checking the output against the expected calculations. Going forward, course materials, compiler feedback, documentation, and small test cases are resources I can continue using to understand problems and debug them more effectively.

### What skills from this project will be particularly transferable to other projects or course work?

File handling, data transformation, testing, and debugging are all skills I can apply to other projects. Although this program uses a basic temperature conversion, the overall process of reading information, applying logic, and exporting results comes up regularly in software development. I can connect that process to work involving Python scripts, APIs, and automation, where data often needs to be retrieved, processed, and passed to another system.

### How did you make this program maintainable, readable, and adaptable?

I used descriptive variable names, comments that explain the purpose of important sections, and a separate function for the Fahrenheit-to-Celsius calculation. Keeping the conversion logic separate makes it easier to review and update without changing how the program reads or writes files. I also included checks for file errors, which helps make failures more understandable. These choices make the program easier to follow and provide a foundation for future improvements.
